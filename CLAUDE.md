# CLAUDE.md — working rules for this repository

This is **dartway.dev**: the Docusaurus site for the DartWay framework. Deployed to GitHub Pages
from `master` by `.github/workflows/deploy.yml`, served on the apex domain via `static/CNAME`.

Read [STRATEGY.md](STRATEGY.md) first. It holds the concept, the decisions taken and why, and the
roadmap. [TASKS.md](TASKS.md) is the working list — what is open, what is done, and what is waiting
on the owner rather than on work. Keep it current; a task list that has to be reconstructed from
memory each session is not one.

This file is only the operating rules.

---

## The one rule that matters

**`docs/` and `i18n/ru/` are generated. Never edit either by hand.**

Every file under `docs/` is a copy of `docs/` in the [`dartway/dartway`](https://github.com/dartway/dartway)
monorepo, produced by `npm run sync-docs`. Every file under `i18n/ru/` is a translation of the
English source in `learn/` and `src/`, produced by `npm run translate`. A hand edit to either
survives until the next run and then disappears without a trace.

If a documentation page is wrong, the fix belongs in the monorepo, in the same pull request as the
code it describes. Then re-run the sync here. This is deliberate: the site's docs previously drifted
so far from the framework that the published quick start told readers to clone a template the CLI no
longer uses.

If a Russian page is wrong, there are two cases. If the English says the wrong thing, fix the English
and re-translate. If only the Russian is wrong — a clumsy sentence, a term nobody says — the fix goes
into the prompt in `tools/translate.mjs`, not into the output. A prompt fix improves every page; an
output fix improves one page until the next run. Bump `PROMPT_VERSION` in that file and everything
retranslates.

Everything else in the repo is written here, by hand, normally, **in English** — see the next section.

## Layout

| Path | What it is |
|---|---|
| `docs/` | **Generated.** Framework documentation, synced from the monorepo |
| `i18n/ru/` | **Generated.** The Russian site, translated from the English source |
| `learn/` | Hand-written. The competency map — served at `/learn` |
| `src/pages/` | Hand-written. Landing page and any standalone pages |
| `src/clientModules/` | Runs on every page. Currently the analytics client |
| `src/css/`, `src/components/` | Hand-written. Theme and shared components |
| `static/` | Assets served verbatim. `CNAME` sets the custom domain — do not remove it |
| `scripts/` | The docs sync, the llms.txt generator, the link checker |
| `tools/` | Operator scripts — stats, worker secret, token, the translator |
| `analytics/` | The Cloudflare worker behind the page counter |
| `sidebars.ts`, `learnSidebars.ts` | Both autogenerated from folder structure |

## Commands

```bash
npm start          # dev server
npm run build      # production build — must pass before anything is pushed
npm run serve      # serve the built site
npm run typecheck

npm run sync-docs    # pull docs from the monorepo (default branch: master)
npm run check-links  # verify every external link under learn/ resolves
npm run stats        # read the page counter

npm run translate            # regenerate i18n/ru for whatever changed in English
npm run translate -- --check # report what is stale, write nothing, exit 1
npm run translate -- --force # everything, ignoring the manifest
```

`npm run translate` runs the `claude` CLI, so it needs nothing configured beyond that CLI being on
PATH — but it is an operator command, not a build step. It costs real tokens and takes minutes.
Incremental by default: it hashes each English source into `i18n/ru/.translate-manifest.json` and
only re-runs what changed.

## Conventions

**Write in English. The Russian is generated.** The site is bilingual — English at the root, Russian
at `/ru` — but only one of those is a source. Never write Russian prose into `learn/`, `src/` or a
translation file; write the English and run `npm run translate`. This is the rule the previous
attempt broke, by keeping a second language object inside the landing component where every edit had
to be made twice and, in practice, was not.

A new user-visible string in a component goes through `translate()` from `@docusaurus/Translate`,
with an explicit `id`. If it does not, it will never reach the Russian site — `npm run translate`
finds strings by extracting those calls, and silently has nothing to translate for the rest.

**The documentation has no Russian version, by design.** The docs plugin is off for every locale but
the default, so `/ru/docs/*` returns nothing rather than serving English text under a Russian URL.
Two consequences worth knowing before touching either: an internal `<Link to="/docs/…">` on a page
that also renders under `/ru` fails the build, so those have to be plain `<a href>`; and
`src/localeRoutes.ts` is what tells the navbar and the `hreflang` tags that the rule exists. Add a
second English-only section and it goes in that file.

**`onBrokenLinks: 'throw'`.** A single bad link fails the build, and therefore the deploy. Always run
`npm run build` before pushing, especially after a sync.

**`markdown.format` is `'detect'`.** `.md` is parsed as CommonMark and only `.mdx` as MDX, because
the synced docs are full of generics like `DwCrudConfig<T>` that MDX would read as JSX. Do not
switch it back to gain a component in one page — use an `.mdx` file for that page instead.

**Numeric prefixes drive ordering.** Docusaurus strips `1-`, `01_` and similar from folder and file
names when building URLs, so `docs/1-getting-started/quick-start.md` serves at
`/docs/getting-started/quick-start`. Renaming a folder upstream changes a public URL — worth
noticing in a sync diff.

**The blog is off deliberately.** `preset-classic` enables it unless told otherwise and publishes an
empty `/blog` with no posts. Turn it on when there is something to put in it.

## Adding a competency-map page

Written here, in `learn/`. **Read [learn/PAGE_TEMPLATE.md](learn/PAGE_TEMPLATE.md) first** — it holds
the section-by-section shape and the reasoning behind each part. Copy it rather than improvising: a
map whose pages each have their own layout stops being a map.

The two rules that matter most:

- **These are maps, not tutorials.** A page frames a topic, says what competence looks like at each
  level, and points at the best material that already exists. It does not teach the topic.
- **Neutral about Flutter development, not about DartWay.** The reader arrived with a problem, not
  with an interest in our framework. Where DartWay is a genuine answer it appears at the end of a
  page, never as the premise.

Every external link must resolve — `npm run check-links` enforces it, and it is the check that keeps
the Resources sections worth having. The Russian copy inherits that guarantee only because the
translator refuses any page whose link set changed, so it is checked once, in English.

Write the page in English, then run `npm run translate` in the same commit. A page that ships without
it is a page the Russian sidebar lists and the Russian site serves in English.
